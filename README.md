# TRACE – English Speech Recognition

**TRACE (Topic Recognition and Action Coordination Engine)** is a local, offline English speech-to-text prototype. This repository currently contains the speech-recognition component: a custom CNN + bidirectional GRU (BiGRU) acoustic model trained with Connectionist Temporal Classification (CTC), with greedy decoding for transcription.

The application provides two main areas:

- **Verified Demo Recordings:** Load selected LibriSpeech recordings and view their generated transcripts. 
- **Try Your Own Audio:** Upload or record an English audio sample and view the transcription generated by the trained model.

TRACE does not call cloud speech-recognition APIs.

## Features

- Offline inference using a locally stored trained model.
- Audio upload and microphone recording through a Gradio interface.
- Audio loading with SoundFile and resampling with torchaudio.
- Log-Mel feature extraction.
- CNN + 5-layer bidirectional GRU model with CTC.
- Greedy CTC decoding.
- LibriSpeech reference recordings for a quick demo.
- Training, evaluation, and metric history files.

## Requirements

- Windows, macOS, or Linux.
- **Python 3.13** recommended (the development environment used Python 3.13.x).
- Git.
- Git LFS, required to download the model checkpoint files.
- Internet access for the initial setup and dataset download. After dependencies, checkpoint, and dataset are present, inference runs locally.
- A CPU is sufficient for inference. A compatible NVIDIA GPU is optional; install the appropriate PyTorch build for your hardware if using one.

## Setup on a new computer

Run the commands from the folder where you want to place the project.

### 1. Install Git LFS

Install Git LFS from <https://git-lfs.com/> if it is not already installed. Then run:

```powershell
git lfs install
```

### 2. Clone the repository and download the checkpoint

```powershell
git clone https://github.com/MariaZahid62/TRACE--ASR-MODEL.git
cd TRACE--ASR-MODEL
git lfs pull
```

`git lfs pull` downloads the tracked `.pt` model files. The app uses:

```text
checkpoints_2000/best.pt
```

If the checkpoint file is missing or Git LFS downloaded only a pointer file, check that Git LFS is installed and run `git lfs pull` again.

### 3. Create and activate a virtual environment

```powershell
py -3.13 -m venv venv
```

Activate it in PowerShell:

```powershell
.\venv\Scripts\Activate.ps1
```

If PowerShell blocks activation for this terminal session, run:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\venv\Scripts\Activate.ps1
```

The terminal should show `(venv)` after activation.

### 4. Install Python dependencies

Upgrade pip and install the project requirements:

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

**PyTorch note:** `torch` and `torchaudio` must be compatible versions. The requirements file installs both packages. If pip cannot find a compatible build for your operating system or Python version, use the official PyTorch installation selector at <https://pytorch.org/get-started/locally/> and install a matching `torch`/`torchaudio` pair for CPU or your GPU. Then run `pip install -r requirements.txt` again.

### 5. Download the LibriSpeech dataset

Download LibriSpeech from OpenSLR:

<https://www.openslr.org/12/>

TRACE's current configuration uses these two splits:

- `train-clean-100` – training data.
- `dev-clean` – validation data and the verified demo recordings used by the app.

Extract the downloaded archives so the folders are arranged exactly like this from the project root:

```text
TRACE/
└── data/
    └── LibriSpeech/
        ├── train-clean-100/
        │   ├── 103/
        │   └── ...
        └── dev-clean/
            ├── 1272/
            ├── 3170/
            ├── 6313/
            ├── ...
```

Do not leave the audio files inside an extra nested `LibriSpeech` or archive folder. The app expects the demo audio under `data/LibriSpeech/dev-clean/`.

The dataset is intentionally excluded from Git. Each team member downloads and extracts it locally.

### 6. Run the application

From the TRACE project root, with `(venv)` active:

```powershell
python app.py
```

Open this address in your browser:

<http://127.0.0.1:7860>

Use **Verified Demo Recordings** to play a sample and see its generaed transcript. Use **Try Your Own Audio** to obtain prediction from the model.

## Evaluate the existing checkpoint

To evaluate the saved 2000-sample model using the configuration in the repository:

```powershell
python -m src.train --config configs/english_2000_config.yaml --eval-only --checkpoint checkpoints_2000/best.pt
```

This evaluates the existing checkpoint; it does not start a new training run.

## Training (optional)

The trained checkpoint is already included through Git LFS, so a teammate does **not** need to train the model just to run the app or test inference.

If training is intentionally required, run:

```powershell
python -m src.train --config configs/english_2000_config.yaml
```

Training can take a long time on a CPU-only computer. It is not part of the normal setup process.

## Model and evaluation notes

The included `checkpoints_2000/best.pt` is the selected checkpoint from the 2000-sample experiment. The training history is saved in `checkpoints_2000/history.json`.

The experiment's validation WER was approximately 1.042 in epoch 1 and 1.066 in epoch 2; epoch 2 CER was approximately 0.599. These results show that the model is an experimental prototype and that transcription accuracy is still a limitation.

## Troubleshooting

**The app says the checkpoint is missing**

Run `git lfs pull` from the repository root and confirm that `checkpoints_2000/best.pt` exists and is a real model file, not a small text pointer.

**A verified demo recording cannot be found**

Confirm that the `dev-clean` split has been extracted into `data/LibriSpeech/dev-clean/` and that the speaker/chapter folders are present.

**A Python package fails to install**

Confirm that the virtual environment is active and that Python 3.13 is being used. For PyTorch installation issues, install a compatible `torch` and `torchaudio` pair from the official PyTorch selector.

**The app is already using port 7860**

Stop the other running TRACE app with `Ctrl + C` in its terminal before starting it again.
